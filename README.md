# وكالة براديس — منصة السفر والسياحة والخدمات (B2C & B2B)

نظام خلفي (Backend API) متكامل لوكالة سفر وسياحة وخدمات أعمال، مبني بـ
**FastAPI** و **PostgreSQL** باستخدام معمارية طبقات نظيفة (Clean
Architecture).

## نظرة عامة على الخدمات

- **B2C**: تذاكر طيران، فيز، إقامات، تأمين طبي للجمهور مباشرة.
- **B2B**: أسعار خاصة ومحفظة إلكترونية/حد ائتماني للفرانشايز والوكلاء
  الفرعيين.
- **دفع هجين**: تحويل بنكك (برفع إشعار) أو فيزا، مع تأكيد يدوي إلزامي من
  الموظفين قبل إنجاز أي طلب.
- **لوحة تحكم تنفيذية**: تعديل ديناميكي كامل، متابعة الأرباح، وتحكم يدوي
  حصري بسعر صرف الجنيه السوداني (SDG).
- **تتبع لحظي**: حالة كل طلب مرئية للعميل والوكيل مع سجل تدقيق كامل.
- **Leads**: استقبال طلبات اهتمام لخدمات مستقبلية (لوجستيك، دعاية وإعلام).
- **تسجيل دخول عبر قوقل**: للعملاء الزوار، بجانب الدخول التقليدي
  (بريد/هاتف + كلمة مرور) — يتطلّب `GOOGLE_CLIENT_ID`/`VITE_GOOGLE_CLIENT_ID`
  فعليَين (اتركهما فارغين حتى تتوفر بيانات اعتماد حقيقية).
- **إشعارات إيميل**: تأكيد استلام الطلب وتحديثات حالته تلقائياً عبر
  SMTP عام (يتطلّب `SMTP_HOST`/`SMTP_FROM_EMAIL`، وإلا يُتجاوَز الإرسال بصمت).
- **متطلبات المستندات لكل خدمة**: قائمة قابلة للتعديل الكامل من الإدارة
  (المستندات المطلوبة لكل تذكرة/فيزا/إقامة...)، تظهر للعميل عند إنشاء طلب.

## هيكل المشروع (Clean Architecture)

```
app/
  core/        إعدادات، قاعدة البيانات، JWT/bcrypt، RBAC، معالجة الأخطاء، تخزين آمن
  models/      نماذج SQLAlchemy (تطابق مخطط قاعدة البيانات المعتمد)
  schemas/     DTOs عبر Pydantic (Request/Response)
  services/    منطق العمل (Business Logic) لكل ميزة بمعزل عن الراوترز
  routers/     نقاط النهاية (Endpoints) — طبقة رقيقة تستدعي services فقط
alembic/       ترحيلات قاعدة البيانات (migrations)
frontend/      واجهة React + TypeScript + Tailwind (لوحة التحكم)
```

## القواعد المعمارية الصارمة المطبّقة

1. **RBAC صارم**: كل Endpoint حساس محمي بـ `require_roles(...)` من
   `app/core/permissions.py`، مع أدوار: `admin`, `employee`, `agent`,
   `customer`.
2. **الجنيه السوداني (SDG) يدوي حصرياً**: لا يوجد أي استدعاء API خارجي
   لجلب أسعار الصرف في كامل الكود؛ التحديث يتم فقط عبر
   `PATCH /api/v1/currencies/{code}/rate` بصلاحية `admin`، ويُسجَّل في
   `audit_logs`.
3. **دورة الطلب والدفع**: لا يُؤكَّد أي طلب تلقائياً بعد رفع إشعار بنكك
   أو دفع فيزا. الحالة تبقى `pending` حتى يراجع موظف/مدير الدفع يدوياً
   عبر `PATCH /api/v1/payments/{id}/verify`، وكل انتقال حالة يُسجَّل في
   `order_status_logs` (انظر `app/services/order_service.py`).
4. **الفرانشايز (B2B)**: ثلاثة أوضاع دفع لكل وكيل (`prepaid_wallet`,
   `credit_limit`, `pay_per_order`) مطبّقة في
   `app/services/wallet_service.py`، مع تسجيل كل حركة في
   `agent_wallet_logs`.
5. **حماية المرفقات**: صور الجوازات وإشعارات بنكك تُحفظ في مسار خاص غير
   عام، ولا تُقدَّم إلا عبر رابط موقّع محدود الصلاحية
   (`app/core/storage.py` + `app/routers/files.py`).
6. **رسائل الأخطاء بالعربية**: أي استثناء تطبيقي (`AppException`) يعيد
   رسالة عربية واضحة للواجهة، بينما تُسجَّل التفاصيل التقنية الدقيقة في
   اللوجز الخلفية فقط (`app/core/exceptions.py` + `app/main.py`).

## التشغيل محلياً (Python مباشرة)

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
# عدّل .env: DATABASE_URL, JWT_SECRET_KEY, SIGNED_URL_SECRET

alembic upgrade head                    # ينشئ كل الجداول (migration جاهزة مسبقاً)
python -m scripts.seed_initial_data          # يضيف العملات الأساسية + حساب مدير افتراضي
python -m scripts.seed_agency_services       # يضيف كتالوج خدمات الوكالة الفعلي (39 خدمة)
python -m scripts.seed_service_requirements  # يضيف قوائم المستندات المطلوبة لكل خدمة

uvicorn app.main:app --reload
```

يفتح توثيق تفاعلي تلقائياً على `http://localhost:8000/docs`.

## التشغيل عبر Docker (الأسهل)

```bash
docker compose up --build
```

يشغّل هذا الأمر PostgreSQL وواجهة الـ API معاً، وينفّذ الترحيلات وسكربت
التهيئة الأولية تلقائياً. الـ API تكون متاحة على
`http://localhost:8000/docs`.

بيانات المدير الافتراضي (يجب تغييرها فوراً): البريد
`admin@wakalat-baradis.com`، كلمة المرور `ChangeMe@2026` (أو القيم التي
تحددها عبر متغيرات البيئة `ADMIN_EMAIL` / `ADMIN_PHONE` /
`ADMIN_PASSWORD`).

## تشغيل الاختبارات

```bash
pip install -r requirements-dev.txt
pytest
```

مجموعة الاختبارات تعمل على SQLite في الذاكرة (لا تحتاج PostgreSQL) وتغطي:
مصفوفة انتقالات حالة الطلب، منطق محفظة الوكلاء بأوضاعها الثلاثة، التحديث
اليدوي لسعر الصرف، RBAC، والمصادقة.

## الواجهة الأمامية (Frontend)

واجهة لوحة التحكم مبنية بـ **React + TypeScript + Tailwind CSS v4** مع
دعم كامل للعربية/RTL (خط Cairo) و`lucide-react` للأيقونات، وفق دليل
التصميم في `docs/UI_DESIGN_GUIDELINES.md`. **أولوية التصميم للهاتف
(Mobile-first)**: القائمة الجانبية ثابتة على شاشات الحاسوب فقط، وتتحول
على الهاتف إلى قائمة منسدلة (Drawer) تُفتح بزر في الشريط العلوي.
تشمل حالياً ثماني شاشات كاملة: تسجيل الدخول (بريد/هاتف + كلمة مرور، أو
دخول سريع عبر قوقل)، لوحة التحكم الرئيسية (كروت KPI وجدول طلبات
تفاعلي)، الطلبات (إنشاء طلب جديد مع عرض مستندات الخدمة المطلوبة، ورفع
إثبات الدفع)، المدفوعات (طابور مراجعة يدوية للموظف/المدير)، المستردات
(طابور اعتماد/رفض/تنفيذ للمدير)، الوكلاء (B2B)، الخدمات (كتالوج كامل مع
إضافة/تعديل/حذف/عروض خصم محدودة المدة، وإدارة قائمة مستندات كل خدمة)،
العملات وسعر الصرف، وحسابي (بيانات شخصية وتغيير كلمة المرور). دورة حياة
الطلب الكاملة — من الإنشاء، مروراً بالدفع والمراجعة اليدوية والمعالجة
الخارجية، ورفع المستند النهائي (تذكرة/فيزا)، وحتى الاسترداد إن لزم —
مبنية ومُختبرة حياً عبر المتصفح.

```bash
cd frontend
npm install
cp .env.example .env.local   # عدّل VITE_API_BASE_URL إذا لزم
npm run dev                  # يفتح على http://localhost:5173
```

للتحقق من جاهزية الإنتاج:

```bash
npm run build   # فحص الأنواع (tsc) ثم بناء الإنتاج (vite build)
npm run lint    # oxlint
```
